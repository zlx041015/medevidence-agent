# 简历与面试表达

## 简历项目名

`MedEvidence Agent：面向临床问题的医学证据检索与结论生成系统`

## 简历描述模板

你后面可以按真实完成度改写，但建议保留下面这些关键词：

`设计并实现面向临床问题的证据驱动型 Agent 工作流系统，将医学问答拆解为任务规划、证据检索、结构化抽取、事实核验和结论生成五个阶段，降低医疗场景下大模型直接生成带来的幻觉风险。`

`构建结构化证据表示与引用回溯机制，为每条结论保留来源、相关片段和置信度评分，并通过阈值控制和冲突检测限制低可靠性内容进入最终输出。`

`基于模块化工作流设计预留真实搜索、LLM、人工审核和持久化扩展接口，支持从本地 mock 数据原型逐步演进到可部署的医学信息检索应用。`

## 面试官常问问题

### 1. 为什么不用一个大模型直接回答

建议回答：

`医疗问题对可解释性要求更高。单轮生成虽然简单，但很难追踪证据来源，也不容易控制幻觉。我把流程拆成规划、检索、抽取、核验、生成几个节点，是为了让每一步都有明确输入输出，便于调试和评估。`

### 2. 你怎么控制幻觉

建议回答：

`核心方法不是只靠 prompt，而是通过架构限制。系统先检索证据，再抽取结构化字段，最后只允许 Writer 基于通过核验的证据生成。对于低置信度结论，系统会明确标记不确定性，而不是强行给出确定答案。`

### 3. 为什么 Verifier 不完全交给 LLM

建议回答：

`因为核验阶段更适合显式逻辑。第一版我先用规则和打分来聚合证据支持度，这样更容易解释和调试。LLM 更适合做抽取和语言表达，而不是在高风险场景中完全黑箱地决定真假。`

### 4. 你会怎么继续优化

建议回答：

`优先接入真实指南和 PubMed 检索，再升级到 LangGraph 做持久化和人工审核。之后补充评测集，比较不同检索参数、提示词和核验策略对引用完整率和事实一致性的影响。`

## 你做项目时要刻意保留的材料

这些材料在面试时很有用：

- 架构图
- 一次真实运行的日志截图
- 输入问题与输出结果对照
- 失败案例分析
- 调参前后效果对比

## 一个很重要的提醒

你不是在证明“模型会医学”，而是在证明：

`你会把大模型能力约束成一个更可靠的医疗信息系统。`
