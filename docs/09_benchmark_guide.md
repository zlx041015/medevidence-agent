# Benchmark 指南

## 目标

这份 benchmark 的目标，不是构建一个只覆盖单一专项病种方向的小型示例集，而是为 `MedEvidence Agent` 提供一个面向通用常见病症问题的评测样本集。

它主要服务于以下场景：

- baseline 对比
- 消融实验
- 结果产物导出
- 面试时展示“系统具备通用病症覆盖能力”

## 题型设计

benchmark 中的问题主要围绕四类医学信息任务展开：

1. `treatment`
   关注一线管理或治疗重点

2. `screening`
   关注为什么要做相关筛查或评估

3. `follow_up`
   关注长期随访时应该重点看什么

4. `risk_management`
   关注为什么需要个体化和风险分层

## 风险等级设计

### `high`

通常包括：

- 治疗决策
- 风险控制
- 心血管相关问题
- 需要权衡并发症或长期预后的问题

### `medium`

通常包括：

- 常规筛查
- 长期随访
- 生活方式管理
- 一般教育性问题

## 字段说明

每条 benchmark 记录包含：

- `question_id`
  唯一编号

- `question`
  自然语言问题文本

- `question_type`
  题型分类

- `risk_level`
  风险等级

- `gold_keywords`
  理想检索词

- `gold_sources`
  推荐来源 ID

- `gold_claim`
  理想核心结论

- `needs_human_review`
  是否应触发人工审核

## 为什么这样设计

### 1. 不追求单病种极深，而强调广谱通用

因为这个项目的定位是：

`通用常见病症问题的医学证据系统原型`

不是某一个专科疾病的科研级知识库。

### 2. 优先覆盖临床和生活中常见场景

这样更适合：

- 面试讲述
- 产品展示
- 工程型项目评测

### 3. benchmark 与系统能力尽量对齐

当前项目采用的是：

- mock / hybrid_mock 来源
- 规则 + LLM 双路径
- 轻量 RAG
- verifier 风险核验

所以 benchmark 也优先围绕：

- 常见病
- 常见管理问题
- 可由指南/综述类来源支撑的问题

## 使用建议

### 适合用来做

- 方法横向比较
- benchmark 展示
- 失败案例分析
- 项目定位说明

### 不适合直接宣称

- 已达到正式临床研究级 benchmark
- 已覆盖完整指南语义层级
- 已具备专家人工标注严谨性

## 后续扩展建议

1. 对每个病种增加更多不同难度层级的问题
2. 按系统、专科或临床课程模块进一步细分
3. 为每条记录增加更细的证据等级标签
4. 增加人工盲评字段
5. 增加失败标签，例如：
   - 容易漏召回
   - 多来源冲突
   - 高风险需人工审核

## 一句话总结

这份 benchmark 的意义，在于把 `MedEvidence Agent` 从“少数专项病种示例”升级成“面向通用常见病症问题的可评测医学信息系统原型”。
