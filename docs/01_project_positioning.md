# 项目定位

## 项目名称

`MedEvidence Agent: 面向临床问题的医学证据检索与结论生成系统`

## 目标用户

- 医学生
- 临床科研初学者
- 医学信息工程方向学生
- 想做医疗 AI 应用的候选人

## 核心问题

普通聊天式 LLM 在医疗场景有两个明显问题：

1. 它会直接生成结论，但不一定有证据来源
2. 它可能把过时指南、模糊表述、推测性内容混在一起

所以这个项目必须强调：

- `evidence first`：先找证据，再生成结论
- `structured workflow`：把复杂任务拆成多个节点
- `human review`：高风险内容保留人工审核入口

## 为什么不直接做“医学问答机器人”

因为医学问答机器人太泛，技术上也容易被面试官追问：

- 你的知识从哪里来？
- 怎么避免幻觉？
- 怎么处理冲突指南？
- 怎么证明答案可靠？

这个项目的优势在于你可以正面回答这些问题，因为系统里天然有：

- 检索节点
- 抽取节点
- 核验节点
- 引用节点
- 置信度机制

## 你在面试里应该怎么定义这个项目

一句话版本：

`这是一个面向临床问题的证据驱动型 Agent 工作流系统，用于将医学问题转化为可追溯的结论草稿，而不是直接生成不可验证的答案。`

扩展版本：

`我把医学问题回答拆成规划、检索、抽取、核验、生成五个阶段，核心设计目标是降低医疗场景下大模型幻觉风险，并通过结构化证据和引用回溯提升结果可解释性。`

## 为什么这个项目适合你

你的背景不是纯 CS，本项目能让你形成交叉优势：

- 医学理解能力
- 医疗信息化场景认知
- AI 应用工程实现
- 英文资料和指南检索能力

## 最终交付形式

建议你把项目做成以下三个输出：

1. 命令行或 Web 输入临床问题
2. 输出带引用的结构化回答
3. 展示执行日志与证据链

这样既能用于简历，也能当面试 demo。
